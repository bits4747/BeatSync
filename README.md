# BeatSync

![icon](assets/icon.svg)

把音乐批量转成你需要的速度。

[English](README.en.md) | 中文

- **跑者**：让音乐适配你的步频，每一步都踩在节拍上。
- **乐手**：按指定 BPM 练习基本功时可以听着音乐；可以精确调整音乐 BPM

BeatSync 避免大幅度改变音乐速度——**节拍器恒定以目标速度打拍，音乐只做最小幅度的变速。**

## 变速逻辑详解

把音乐挪到目标速度的 **1/n 倍或 n 倍**（n 为整数）

1. **测速**：检测原速 A（或手动指定）。检测值按实测报告，**不做倍频折叠**——
   测到 60 BPM 就报 60 BPM（v1.1.0 起；旧版会把慢歌折叠到 [70,180) 区间）。
2. **选方案**：在所有候选里选使变速幅度最小方案行动。
3. **守上限**：速度变化必须落在允许区间内，否则换方向；两个方向都超上限则跳过。

### 示例

目标 180 BPM，默认上限：放慢 20%、加快 50%（可调整）

| 原速 | 结果                                |
| ---- | ----------------------------------- |
| 60   | 音乐 60 **不变速**，每拍敲 3 下     |
| 85   | 音乐 90（+5.9%），每拍敲 2 下       |
| 100  | 音乐 90（−10%），每拍敲 2 下        |
| 120  | 音乐 180（+50%），每拍敲 1 下       |
| 360  | 音乐 360 **不变速**，每 2 拍敲 1 下 |

上表对**自动检测**与**手动指定原速**都成立。已知限制：节拍检测对
非 4/4 曲目（3/4、6/8、half-time）和稀疏打击乐可能落到倍频/分频上，
误检值会直接反映在报告里；拿不准时请手动填原速。

## 优势一览

- **最小变速**：音乐只被挪到与目标速度成简单倍率（n 倍或 1/n 倍，n 为整数）的位置上，在保证节拍顺耳的前提下选择最小变速策略。
- **加速 / 减速上限可选**：分别设定"最多放慢""最多加快"多少，超出上限的音乐宁可不处理，也不硬拉崩坏听感。
- **精准测速 + 节拍器不漂移**：测速用自相关与梳状网格精修，稳定速度的歌曲能精确到 0.1 BPM 量级；节拍器不是按固定间隔机械叠加，而是直接落在音乐自己的节拍时间轴上，因此不会越敲越偏、错拍。
- **音色可选、相对音量可选**：六种打击音色可试听挑选，音量按歌曲自身响度自动匹配、相对大小可调。
- **批量处理：**批量操作，一键出歌。
- **多种输出格式：**可选  WAV / MP3 / FLAC；MP3 默认**跟随输入文件的码率**（不降码率），也可手动指定 320/256/192/160/128 等档位
- **保持文件夹层级**：批量处理整个曲库时，输出目录完整镜像输入的文件夹结构，不会把所有歌堆成一层；不需要时可在界面上关掉（关掉后平铺在输出目录根部）。
- **界面中英双语**：右上角"中 / EN"按钮一键切换

## 命令行（仅源码运行）

> **安装版没有命令行入口。** 安装出来的 `BeatSync.exe` 是图形界面程序，
> 不接受命令行参数、也不会往控制台输出（双击和带参数启动都只会打开界面）。
> 想用命令行，请按[从源码运行](#从源码运行开发者)装好 Python 与依赖后，在源码目录里执行下面的命令。

图形界面之外也提供完整的命令行入口。

```bash
# 转到 180 BPM
python tempo_converter.py song.mp3 -t 180

# 加木鱼节拍器
python tempo_converter.py song.mp3 -t 180 --metronome woodblock

# 批量转换整个文件夹（含子目录）
python tempo_converter.py ./music -t 180 --recursive

# 统一输出目录（保留原文件夹层级）
python tempo_converter.py ./music -t 180 --recursive -o D:\out

# 同上但全部平铺
python tempo_converter.py ./music -t 180 --recursive -o D:\out --no-mirror-dirs

# 自定义变速上限
python tempo_converter.py song.mp3 -t 180 --max-slowdown 15 --max-speedup 30

# 只测速，不转换
python tempo_converter.py song.mp3 --detect-only

# 手动指定原速，跳过检测
python tempo_converter.py song.flac -t 90 --bpm 88

# 精确拉伸到目标速度
python tempo_converter.py song.mp3 -t 180 --strict

# 分段变速：歌里中途变拍时，自动找到变拍点，每段各按最小变速规则处理
# （默认就是自动分段，通常不用写这个参数；--segments off 可关掉，on 为强制分段）
python tempo_converter.py song.mp3 -t 180 --segments on
```

默认中文输出；加 `--lang en` 可让命令行输出与报告全部改用英文。
全部参数见 `python tempo_converter.py --help`（中文）或 `--lang en --help`（English）。

### 参数速查

| 参数 | 说明 |
|---|---|

| `--mp3-bitrate` | mp3 输出码率：`auto`（默认，跟随输入文件）/ `320` / `256` / `224` / `192` / `160` / `128` / `112` / `96` |

## 分段变速（变拍歌）

**默认就是 `auto`**：整曲按一个检测到的 BPM 处理，但若检测到曲内明显变拍（段间速度差 ≥15%），会自动切成速度段落，每段各按最小变速规则独立处理。也可以显式 `--segments on` 强制分段、`--segments off` 关掉（或界面上的"自动分段变速"开关）。

为什么需要它：像 Rush 的《YYZ》这类前奏与主体拍速不同的曲子，整曲一刀切（140→180，×1.28）会让前奏的节拍器完全错位——前奏自身脉冲在 208 BPM 附近，拉完约 266，与 180 的点击不同频。分段后前奏按自己的速度处理，节拍器就踩上了。

分段流程：

1. 在速度曲线（log-tempo）上做最小二乘变点分段，恒速歌不误分（只有一段时自动退回整曲处理；段间速度差不到 15% 也不分，避免为几个百分点引入接缝）；
2. 每段各自测速、各自套用原有"最小变速"规则出方案；
3. **对位质量闸门**：用"拍点处的起音强度 ÷ 段内平均起音强度"给每段的拍网格打分（>1 表示拍点落在起音上，≈1 表示网格与音乐无关）。分数 <1.10 的段说明它的网格踩不准，会被并进更可信的邻段重测，而不是硬敲；
4. 拼接点两侧都搜索低能量处下刀，做 5 ms 等功率交叉淡化，接缝不超过音乐自身鼓点瞬态（报告备注里若出现"接缝评分 >1"则提示人工听检）；
5. 节拍器沿每段自己的拍网格敲，跨段不错拍；
6. **某段按当前上下限算不出可行方案时**（例如 6 秒的过渡段"加速差一点、减速也差一点"），`auto` 会把它并进速度更近的邻段重测——只要合并后可行就照常出文件，**绝不因为一小段把整首歌丢掉**；`on`（强制分段）则保持严格语义：任一段越限即**整首不做变速**（不生成文件，备注以「跳过：」开头），不会只变可行的那几段，否则交接点两侧速度对不上。

报告仍是一行：多段的检测 BPM / 拉伸后 BPM / 速度变化用 ` / ` 并列，逐段明细写进"备注"；界面还会把每段速度并排标出（如 `100→90｜154→180`）。恒速歌走 `auto` 时行为与单速路径完全一致（检测到只有一段就退回整曲处理）。

实测（《YYZ》，目标 180）：整曲单速 vs 自动分段，四个区域的"命中比"全部改善——

| 区域 | 整曲单速 | 自动分段 |
| --- | --- | --- |
| 前奏 0–32.9s | 0.946（比随机还差） | **1.531** |
| 过渡 32.9–42.6s | 0.858 | 0.922 |
| 主体 42.6–253.2s | 1.220 | **2.021** |
| 尾奏 253.2–267s | 0.980 | 1.118 |

自动分出的两段是 `0–42.6s @102.8 → 90 BPM（−12.5%，每拍敲 2 下）` 与 `42.6–267s @140.7 → 180 BPM（+27.9%，每拍敲 1 下）`，两段节拍器都落在 180。

## 渐变速度（渐快 / 渐慢）

有些曲子不是"在某处换速"，而是**一路渐快或渐慢**（常见于摇滚/爵士的收尾加速、电子乐的 build-up）。这种曲子上整曲单速是错的：整曲会按平均速度拉伸，前半段偏快、后半段偏慢，节拍器从头到尾都不在拍上。硬切分段也不对——每段只有两三秒，既算不出可行方案，接缝还会密集到能听出来。

**程序会自动识别"渐变"并改用分块拉平**，不需要额外开关（跟随"自动分段变速"总开关）：

1. 在起音包络上逐窗测速（窗长随时长自适应，3–10 秒），得到一条随时间变化的速度曲线；
2. 由曲线判定速度形状，分成 `constant`（恒速）/ `step`（阶跃变拍）/ `ramp_up` / `ramp_down`（渐变）/ `wave`（弹性波动）几类。判据是曲线平滑后的**净漂移量、总变差、秩相关系数与单窗最大跳变占比**——渐变是"变化均匀铺开、方向一致"，阶跃是"某一处突然跳"，两者靠单窗最大跳变占总变差的比例区分；
3. 识别为渐变后，建一条跟随渐变的拍网格（`beat_track` 与"速度曲线积分"两条候选都建，各自吸附相位后按**网格点上的起音能量**择优——错网格的余点会落在两个峰之间，得分自然低）；
4. 把拍点按误差预算（默认 25 ms）贪心并成若干块，每块用**一个恒定拉伸比**；块边界落在拍点上；
5. 逐块拉伸后做 5 ms 等功率交叉淡化拼接，接缝不产生咔哒；
6. 节拍器沿每块的拍网格敲，全曲都踩在拍上。

报告里渐变曲的写法是区间形态：`检测BPM = 140.0→110.0`、`检测方式 = 自动检测·渐变`、`拉伸比 = 0.8599~1.0797`；界面显示为 `渐变拉平 140.0→110.0 ⇒ 180.0 · 分 9 块`。

实测（合成素材，30 秒，每拍一个瞬态，目标 120 BPM）：

| 素材 | 形状判定 | 分块 | 输出实测 |
| --- | --- | --- | --- |
| 渐慢 140→110 | `ramp_down`（drift −0.276，peak 0.037） | 7 块，速率 0.858~1.086 | 120.2 BPM，局部速度极差 ≈0 |
| 渐快 100→140 | `ramp_up`（drift +0.376，peak 0.049） | 8 块，速率 0.859~1.143 | 120.2 BPM，局部速度极差 ≈0 |
| 陡渐变 90→150 | `ramp_up`（drift +0.565） | 9 块，速率 0.819~1.272 | 120.2 BPM，接缝评分 0.059 |
| 恒速 120 | `constant`（var 0.003） | — | 不误触，走原路径 |

边界与已知限制：

- **每块仍受加减速上限约束**（默认最多放慢 20%、最多加快 50%，可用 `--max-slowdown` / `--max-speedup` 放宽）。若渐变跨度太大、算不出可行分块，会**退回整曲单速**并在备注里说明原因（"渐变速度：需要的变速超出加减速上限……按原方式处理"），绝不丢文件。
- 渐变判定需要至少 6 秒素材、分块拉平需要至少 8 秒；更短的曲子走原路径。
- 相位声码器会轻微涂抹瞬态（打击乐密集的段落听起来会稍"糊"），这是拉伸算法的固有代价，不影响节拍对齐。
- 手动指定 `--bpm` 时不走渐变判定（以你给的速度为准）。

## 输出说明

**命名**：`原名_目标bpm.扩展名`（例：`song_180bpm.wav`），重名时依次加 `_1`、`_2`、`_3`。

**位置**：默认输出到各文件所在目录的 `tempo_converted/`；
用 `-o` 指定统一目录后按输入层级镜像。

**报告**：CSV 格式，默认写到当前目录 `conversion_report.csv`。

## 项目结构

**这是源码仓库的结构**（从源码运行或二次开发时看到的文件）。
安装版不会释放这些 `.py` 文件——它只有一个 `BeatSync.exe`、一个 `_internal\` 目录，

## 界面语言

图形界面**默认中文**，右上角"中 / EN"按钮（在日/夜间模式按钮左侧）可在中英文之间一键切换。

- **切换范围**：界面上的全部文案——文件名列、参数标签、速度上限提示、音色名（Beep / Woodblock / Cowbell / Click / Sidestick / Clap）、按钮、进度与结果提示、弹窗提示。
- **按钮自身提示**：中文界面下按钮显示"中 / EN"并把鼠标提示指向"切换到 English"，英文界面下反过来。
- 桌面版切换语言后，**日志、结果备注、节拍关系、CSV 报告**都由后端按同一语言生成，英文界面不会露出中文。
- **tkinter 备选界面**同样带右上角"中 / EN"按钮：切换即重建界面，已添加的文件与所有参数原样保留。转换参数与桌面版对齐：有"保持原来的文件夹层级"复选框（没填输出目录时自动置灰）、"最多放慢 / 最多加快"两个上限输入框（0–100，默认 20 / 50）、节拍器相对音量除滑块外还有可直接输入 dB 数值的输入框，均实时同步。
- **命令行**（仅源码运行）默认中文；加 `--lang en`（或设环境变量 `BEATSYNC_LANG=en`）可让运行输出与 CSV 报告全部改用英文。`--lang` 只改显示语言，不影响任何算法行为。
